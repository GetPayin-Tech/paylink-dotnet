# Contributing

## Setup

```bash
dotnet restore
dotnet build
dotnet test
```

The test suite (`tests/Paylink.Tests`) runs on `net8.0` and reuses the shared
golden-signature fixtures. The library multi-targets `net8.0` and `netstandard2.0`.

## The one thing to get right: signature parity

The SDK's core job is reproducing a byte-exact, order-sensitive HMAC that the server
rebuilds independently. The server signs
`base64(hmac_sha256(implode('', Arr::except($request->validated(), [...]))))`, and
Laravel's `validated()` returns fields in **`rules()` order**, skipping absent ones.

So **the order of fields in `src/Paylink/Internal/FieldOrders.cs` must match the order
of keys in the endpoint's FormRequest `rules()`**, minus `token`/`signature` (and
`payment_mode`, which is sent with `signed: false`).

When you touch an endpoint:

1. Open the matching FormRequest under
   `app/Http/Requests/Application/ExternalPaymentIntegration/` in the PayLink repo and
   read `rules()` top to bottom.
2. Mirror that order in the `EndpointSpec`. `SignedBody.Build` signs the coerced
   values in that order — the compiler cannot verify ordering for you.
3. Add a golden vector.

### Golden vectors

`tests/Paylink.Tests/golden-signatures.json` is shared with the JS and Python SDKs and
generated by PHP using the same primitive the server uses. `GoldenSignatureTests`
asserts both that `Signature.Build(values)` produces `expected` and that
`SignedBody.Build` derives the same signature from structured input.

**Adding a field to an endpoint without adding a golden case leaves that field's
position untested.**

## Webhooks sign by opt-out — the mirror-image trap

Requests sign by opt-**in**: `FieldOrders` lists exactly what gets signed. Webhooks are
the opposite. `PaymentIntegrationWebhookJob` copies the whole payload and `unset()`s a
fixed exclusion list before hashing, so a field is signed if added before that
`unset()` and unsigned if added after (as `auth_code` is).

`OptionalSigned` in `src/Paylink/Webhooks.cs` must mirror that decision: if the server
signs a field it **must** be listed (in the server's order); if the server sends it
unsigned it **must not** be.

## Dependency injection

The SDK is DI-first. New surface should be exposed through an interface, and any new
collaborator should be injected — no static singletons or `new`'d dependencies inside
methods. Container wiring lives in `Paylink.DependencyInjection`.

## Style

- XML doc comments (`/// <summary>`) above members only. **No comments inside method
  bodies.**
- `Nullable` is enabled — keep the build warning-clean.
- Format numbers with `CultureInfo.InvariantCulture`; a machine's locale must never
  shift a signature.

## Releasing

1. Bump the version in **three** places — they must agree: `<Version>` in
   `src/Paylink/Paylink.csproj` and `src/Paylink.DependencyInjection/Paylink.DependencyInjection.csproj`,
   and `PaylinkVersion.Value` in `src/Paylink/Internal/PaylinkVersion.cs` (the
   User-Agent would otherwise report a stale version).
2. Update `CHANGELOG.md`.
3. Tag `v<version>` and publish both packages to NuGet.
